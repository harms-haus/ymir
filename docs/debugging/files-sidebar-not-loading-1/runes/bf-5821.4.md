# bf-5821.4 — Tests for error handling and error display

## Status: pending

## Description
Add tests to verify the server-side error handling and client-side error display work correctly.

## Files
- `crates/ws-server/src/` — backend test module (new or existing)
- `apps/web/src/__tests__/` — frontend tests (new or existing)

## Backend Changes
1. Test: `handle_file_list` returns `FILE_LIST_ERROR` for non-existent worktree path
   - Create an `AppState` with a worktree pointing to `/tmp/nonexistent-path-xyz`
   - Send a `FileList` message
   - Assert response is `ErrorResponse` with `code: "FILE_LIST_ERROR"`
   - Assert error message contains the path
2. Test: `handle_file_list` returns files normally for valid path
   - Create temp directory with files
   - Create worktree pointing to temp dir
   - Send `FileList` message
   - Assert response is `FileListResult` with the expected files
3. Test: `handle_file_list` returns `FILE_LIST_ERROR` when `spawn_blocking` panics (optional, harder to test)

## Frontend Changes
1. Test: ErrorResponse with `FILE_LIST_ERROR` shows error UI
   - Mock WebSocket client sending ErrorResponse
   - Assert error message and retry button are rendered
2. Test: Retry button re-sends FileList request
   - Render component with error state
   - Click retry button
   - Assert FileList message was sent
3. Test: Successful FileListResult after error clears error state
   - Send ErrorResponse, then FileListResult
   - Assert error is cleared and file tree is rendered

## Success criteria
- All backend tests pass: `cargo test -p ymir-ws-server`
- All frontend tests pass: `npm test` or `npx vitest run`
