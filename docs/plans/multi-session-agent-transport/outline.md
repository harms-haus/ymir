# Outline: Multi-Session Agent Transport

## Core Thesis

Enable multiple agent tabs per worktree, each backed by its own ACP agent process (1:1 tab:process). The server generates `agent_tab_id` for each tab and the client uses it to look up `thread_id` (= `acpSessionId`) for rendering. Change the event routing key from `worktreeId` to `thread_id` across the stack. The accumulator maintains state per thread_id; multiple UI tabs pointing to the same thread_id share the same accumulated state (client-side dedup).

## Terminology

| Term | Description | Generated By |
|------|-------------|--------------|
| `agent_tab_id` | Stable key for an agent tab. Server-generated. Client uses it to look up thread_id. | Server |
| `process_id` | Ephemeral, assigned when agent process spawns, changes on restart | Server |
| `thread_id` | = `acpSessionId`. ACP conversation identifier. May be undefined initially. Can be specified to resume a previous conversation. User can change it. | ACP Agent |

## Architecture Rules

1. **1:1 tab-to-process** — each agent tab gets its own dedicated ACP agent process
2. **agent_tab_id is server-generated** — client requests by worktreeId, server creates tab record and returns agent_tab_id
3. **thread_id is ephemeral** — user can switch threads; server loads correct thread in the ACP process
4. **Shared thread_id is CLIENT-SIDE only** — multiple UI tabs read from same accumulated state, each has own process
5. **acp-chat-core** keeps threads separate (accumulates per thread_id) — NO changes needed
6. **acp-ws-bridge** passes thread_id through — minimal changes
7. **Client UI** maps agent_tab_id -> thread_id to look up thread state

## agent_tab_id Lifecycle

1. Client sends `AgentSpawn { worktreeId }` (just the worktree)
2. Server generates `agent_tab_id` (UUID), creates tab record, links to worktree
3. Server spawns agent process for that tab
4. Agent process sends `SessionInit` with `acpSessionId` (= thread_id)
5. Server links `agent_tab_id` -> `thread_id`
6. Client receives `agent_tab_id`, looks up `thread_id` from store, renders thread

## Phase 1: Prototype (Vertical Slice)

### Task 1: Update Protocol Types for Multi-Session
Update `AgentSpawn` to support multiple spawns per worktree (server generates `agent_tab_id`). Add `agent_tab_id` (UUID) to `AgentStatusUpdate` so the client can correlate tabs. Add `agent_tab_id` to `AgentSend` and `AgentCancel` for targeting specific tabs/processes. Update Rust protocol types in `crates/ws-server/src/protocol/agent.rs`, then run `make sync-types` and update TypeScript types. Update all test fixtures.
Dependencies: none

### Task 2: Support Multiple AcpClients Per Worktree (1:1 tab:process)
Change `AcpRuntime.clients` from `HashMap<Uuid, AcpClient>` (keyed by worktree_id) to `HashMap<Uuid, AcpClient>` keyed by `agent_tab_id` (server-generated). Each spawn creates a new entry. Update all `AcpCommand` variants (Spawn, SendPrompt, Cancel, Kill) to use `agent_tab_id` as the routing key. The worktree_id is still passed for CWD resolution but is NOT the HashMap key. Update `AcpHandle` methods to accept `agent_tab_id`.
Dependencies: Task 1

### Task 3: Update Agent Handler to Route by agent_tab_id
Update `handle_agent_spawn()` to generate `agent_tab_id`, create a new `AgentSession` record, and pass it to `AcpRuntime`. Update `handle_agent_send()` to look up agents by `agent_tab_id`. Update `handle_agent_cancel()` to route by `agent_tab_id`. Ensure `AgentStatusUpdate` broadcasts include `agent_tab_id` for client correlation. The handler should also link `agent_tab_id` -> `thread_id` when `SessionInit` arrives.
Dependencies: Task 2

### Task 4: Re-Key Accumulator Threads by thread_id (acpSessionId)
Change `AcpAccumulatorState.threads` Map key from `worktreeId` to `thread_id` (= `acpSessionId`). Update all `AcpAccumulatorAction` variants (`EVENT_RECEIVED`, `USER_MESSAGE`, `FLUSH_THREAD`, `SET_STREAMING`, `REBUILD_FROM_SNAPSHOT`) to use `thread_id` as the routing key. Update `AccumulatedThread` to carry `worktreeId` and `agentTabId` as data fields (not keys).
Handle the timing gap: thread_id is undefined until `SessionInit` arrives. Use `agent_tab_id` as a temporary key, then re-key to `thread_id` on `SessionInit`.
Dependencies: Task 3

### Task 5: Route handleAcpPayload by thread_id
In `yws-transport.ts`, extract `acpSessionId` (= thread_id) from the payload data and pass it to `dispatchAccumulator` as the routing key. On `SessionInit`, perform the re-key from temporary `agent_tab_id` key to `thread_id`. Extract `agent_tab_id` from events where available for tab correlation.
Dependencies: Task 4

### Task 6: Update AcpChat and AgentRuntimeProvider to Read by thread_id
Change `AcpChat` to receive `thread_id` as a prop (looked up from `AgentSessionState.acpSessionId` via `agent_tab_id`). Change accumulator lookup from `threads.get(worktreeId)` to `threads.get(threadId)`. Apply same to `AgentRuntimeProvider`. `AgentPane` uses `agent_tab_id` to find the `thread_id` and passes it down.
Dependencies: Task 5

### Task 7: Update AgentPane to Use Server-Generated agent_tab_id
Update `AgentPane.handleSpawnAgent()` to send `AgentSpawn` with just `worktreeId`. On receiving `AgentStatusUpdate` with `agent_tab_id`, create the tab using that server-generated ID. Update `handleSendMessage()` to include the current tab's `agent_tab_id` in the `AgentSend` message. Support passing an existing `thread_id` to `AgentSpawn` for resuming a previous conversation.
Dependencies: Task 6

## Phase 2: Horizontal Expansion

### Task 8: Shared Thread State (Client-Side Dedup)
When two UI tabs point to the same `thread_id`, they automatically share the same `AccumulatedThread` in the accumulator (keyed by `thread_id`). Verify this works: both tabs update simultaneously. Add UI affordance for connecting a new tab to an existing thread if desired. Each tab still has its own process — sharing is purely client-side state.
Dependencies: Task 7

### Task 9: Temporary Key Migration for Early Events
Harden the timing gap handling between agent spawn (`agent_tab_id` known) and `SessionInit` (`thread_id` known). Buffer or temporarily key events using `agent_tab_id`. On `SessionInit`, migrate the temporary thread to `thread_id`. Handle edge cases: events between spawn and SessionInit, duplicates after re-key, concurrent tab creation.
Dependencies: Task 7
Can run parallel with: Task 8

### Task 10: Update acpSessionManager for Multi-Session
Update `acp-session-manager.ts` to support multiple `SessionController` instances per worktree (keyed by `agent_tab_id`). This is the backward-compatibility path for direct JSON-RPC session management.
Dependencies: Task 7
Can run parallel with: Task 8, Task 9

## Phase 3: Cleanup and Hardening

### Task 11: End-to-End Integration Testing
Test the complete multi-session flow: spawn two agents for the same worktree (each gets its own process via different agent_tab_ids), verify separate event accumulation, send prompts independently, cancel one without affecting the other. Test shared thread_id: two tabs pointing to the same `thread_id` see the same accumulated state. Test edge cases: rapid spawn/teardown, network interruption, tab close while session active, thread_id switching.
Dependencies: Task 8, Task 9, Task 10

### Task 12: Remove Dead Single-Session Code Paths
Clean up remaining `worktreeId`-based routing fallbacks in the accumulator, transport, and UI. Remove or simplify the `acpSessionManager` backward-compat path if no longer needed. Update comments/documentation referencing single-session assumptions.
Dependencies: Task 11

## Expected Outcomes

### Features
- Multiple agent tabs per worktree, each with its own isolated ACP agent process (1:1)
- Server-generated `agent_tab_id` for stable tab identification
- Per-thread event accumulation with `thread_id` as the routing key
- Shared thread state: multiple UI tabs reading the same `thread_id` see the same accumulated state (client-side)
- Session-targeted prompt sending and cancellation via `agent_tab_id`
- Temporary key migration for spawn-to-SessionInit timing gap
- Thread resumption: passing existing `thread_id` to resume a previous conversation

### Required Refactorings
- `AcpRuntime.clients` HashMap: worktree_id key to agent_tab_id key
- `AcpAccumulatorState.threads` Map: worktreeId key to thread_id key
- Protocol types: `AgentSpawn` updated, `AgentSend`/`AgentCancel` get `agent_tab_id`
- `handleAcpPayload`: re-routing from worktreeId to thread_id extraction

### Pitfalls to Avoid
- **Don't lose events during key migration**: Events between spawn and SessionInit must not be dropped
- **Don't break the broadcast model**: Server broadcasts to all clients; thread filtering is client-side
- **Don't mix concerns across boundaries**: acp-chat-core and acp-chat-react remain untouched
- **Don't assume thread_id is always available**: Early events need temporary key strategy (agent_tab_id)
- **Don't break existing single-session workflows**: Must be backward-compatible

### Excluded Scope
- Changes to acp-chat-core (confirmed no changes needed)
- Changes to acp-chat-react (confirmed no changes needed)
- Changes to Rust bridge encoder/decoder (opaque transport)
- Agent process-level changes (agents are already session-aware)
- Shared server-side processes (removed requirement)
- Client-generated agent_tab_id (corrected to server-generated)
